# SPEC: 기초대사량(BMR) 계산기

## 목적

"아무 활동도 하지 않고 누워만 있어도 하루에 최소 얼마의 칼로리를 쓰는지 알고 싶다"는 사용자
문제를 해결한다. 성별·나이·키·체중으로 기초대사량(BMR, kcal/일)을 추정하고, 활동량을
선택하면 여기에 활동계수를 곱한 하루 총 소비 칼로리(TDEE)까지 함께 보여준다. 주 사용자는
다이어트·벌크업 등 체중 관리를 위해 "하루에 얼마나 먹거나/움직여야 하는지" 기준값을 찾는
일반 사용자다.

BMR/TDEE는 여러 공식으로 추정한 값이며 실제 대사량과 차이가 있을 수 있는 추정치다. 질병
진단이나 식단·운동 처방을 대체하지 않는다.

## 핵심 사용자 흐름

1. 성별, 나이, 키(cm), 체중(kg)을 입력한다.
2. 활동량을 5단계 중 일상어 설명을 보고 하나 선택한다(선택하지 않아도 BMR은 즉시 계산된다).
3. BMR(하루 최소 소비 칼로리)을 확인한다.
4. 활동량을 선택했으면 TDEE(활동 반영 하루 총 소비 칼로리)를 함께 확인한다.
5. 계산식에 실제 입력값이 대입된 근거를 확인한다.

## 범위 결정 — TDEE(활동대사량) 포함 여부 (판단 근거)

**결론: Must Have로, 같은 페이지 안에 BMR과 명확히 구분된 별도 섹션으로 포함한다. 별도의
"TDEE 계산기"/"활동대사량 계산기" 페이지는 만들지 않는다.**

- `docs/PRODUCT.md` "계산기 중복 금지" 기준(계산 로직이 실질적으로 다른가 / 검색 의도가 실제로
  분리되는가)으로 보면, TDEE는 별도 계산 로직이 아니라 `TDEE = BMR × 활동계수`라는 BMR의
  단순 곱셈 확장이다. "TDEE 계산기"를 별도 페이지로 만들면 성별·나이·키·체중을 그대로 다시
  입력받아야 하므로, 이름만 다른 얇은 중복 페이지가 된다.
- "기초대사량 계산기"를 찾는 사용자의 실제 의도 상당수는 다이어트/식단 계획을 위한 "그래서
  하루에 얼마나 써야 하는지"이며, BMR 하나만 보여주고 끝내면 정보가 반쪽이라 사용자가 결과를
  보고도 다음 행동(하루 권장 칼로리 파악)을 못 한다.
- 추가 입력 부담이 매우 작다(활동량 1개 select, 설명 문구로 선택 가능 — 전문 지식 불필요).
- 선례: `military-salary`가 "봉급 계산"과 "적금 계산"을 한 계산기 안에서 명확히 구분된
  섹션으로 묶은 것과 같은 패턴을 따른다(서로 성격이 다른 두 결과를 섹션으로 나누되 페이지는
  하나). `d-day-calculator`의 모드 A/B 패턴(역함수 관계)은 TDEE에는 맞지 않는다 — TDEE는
  BMR의 역함수가 아니라 BMR에 종속된 단방향 확장이라 모드 전환(둘 중 하나만 보여주기)이 아니라
  "BMR은 항상 보여주고 활동량을 선택하면 TDEE도 추가로 보여주는" 구조가 맞다.
- 따라서 활동량 선택은 필수 입력이 아니라 선택 입력으로 두고(선택 안 해도 BMR 결과는 항상
  나옴), TDEE는 활동량을 선택했을 때만 추가로 표시되는 별도 결과 섹션으로 취급한다.

## 공식 선택 범위 (판단 근거)

**결론: 사용자에게 공식을 직접 선택하게 하지 않는다.** 계산기가 대표 공식 하나를 기본으로
자동 적용하고, 결과 상세/계산 근거 섹션에만 공식명을 명시한다(메인 결과 타이틀에는 전문
용어를 노출하지 않는다).

- `docs/PRODUCT.md` "계산법을 몰라도 쓸 수 있어야 한다" 원칙상 "Mifflin-St Jeor" vs
  "Harris-Benedict" 중 선택하라고 요구하는 것은 일반 사용자에게 무의미한 전문 용어 노출이다.
- 어떤 공식을 대표 공식으로 채택할지의 1차 출처 근거는 Formula Analyst 몫이다(SPEC 단계에서
  확정하지 않음).
- 다만 신뢰도 보강을 위해, 대표 공식이 아닌 다른 공식의 결과값을 참고용 보조 정보로 함께
  보여주는 것은 Should Have로 둔다(이미 입력받은 값으로 계산 가능해 추가 입력이 필요 없다).

## 체지방률 기반 공식(Katch-McArdle) 포함 여부 (판단 근거)

**결론: Could Have (v1 범위 제외).** 이 공식은 체지방률이라는 추가 입력이 필요하고, 일반
사용자는 자신의 체지방률을 모르는 경우가 대부분이라 입력 부담이 크다
(`docs/DESIGN_SYSTEM.md` "입력 필드 수는 최소화한다" 원칙과 충돌). v1은 체지방률 입력 없이
성별·나이·키·체중만으로 계산하는 공식만 지원한다.

## BMI 계산기와의 차이 (계산기 중복 금지 체크)

`src/calculators/registry.ts`의 `bmi-calculator` 항목과 `tasks/bmi-calculator/SPEC.md`를
확인했다. 아래 네 가지 모두에서 실질적으로 다르다:

- **입력**: BMI는 키·체중(+성인 선택적 허리둘레)만 필요. BMR은 키·체중에 더해 나이·성별이
  계산 결과에 직접 반영되는 필수 입력이다(같은 키·체중이라도 나이·성별이 다르면 BMR이
  달라진다 — BMI는 나이·성별과 무관하게 값이 고정된다).
- **계산 로직**: BMI는 `체중(kg) ÷ 키(m)²`라는 단순 비율 공식 하나뿐. BMR은 성별에 따라
  상수/계수가 다른 선형회귀 공식(체중·키·나이의 가중합 + 성별 상수)이며, 나이 의존적이라
  시간이 지나면(생일이 지나면) 같은 키·체중에도 값이 바뀐다.
- **결과 형태**: BMI는 저체중/정상/과체중/비만 같은 "체중 상태 분류"가 핵심 결과다. BMR/TDEE는
  분류가 아니라 "하루 kcal"라는 연속적인 에너지 소비량 수치가 핵심 결과다.
- **검색/사용 의도**: BMI는 "내 체중이 정상 범위인지"를 묻는 검색 의도. BMR/TDEE는 "하루에
  얼마나 먹거나 움직여야 하는지"를 묻는 식단·활동 계획 의도로, 서로 다른 질문이다.

네 기준 모두 실질적으로 달라 별도 계산기가 타당하다. BMI 계산기의 입력 옵션으로 흡수하는 것도
부적절하다 — BMI 계산기는 "간단한 지표 하나"라는 정체성이 있는데, 나이·성별 필수화와
활동량·공식 breakdown까지 추가하면 화면이 복잡해지고 BMI 계산기 자체의 단순함이 깨진다.

## Must Have

### 입력

- 성별: 필수, `남성`/`여성` 중 선택. 성 정체성 판정이 아니라 공식의 성별 상수 선택에 필요한
  분류임을 도움말로 안내한다(bmi-calculator SPEC의 동일 안내 패턴을 따름).
- 나이: 필수, 만 나이(세) 정수 입력. 생년월일이 아니라 나이를 직접 받는다 — BMR 공식은
  날짜 단위 정밀도가 필요 없고, 나이를 직접 입력하는 것이 생년월일 선택보다 응답 부담이
  작다(`docs/DESIGN_SYSTEM.md` "입력 필드 수는 최소화한다·더 답하기 쉬운 쪽 하나만" 원칙).
  유효 연령 범위(하한/상한)는 대표 공식이 검증된 연령대를 기준으로 Formula Analyst가 1차
  출처로 확정한다 — v1은 성인 대상 공식만 적용하고, 소아·청소년 전용 공식은 범위 밖으로 둔다.
- 키: 필수, cm, 소수 첫째 자리까지 허용.
- 체중: 필수, kg, 소수 첫째 자리까지 허용.
- 활동량: 선택 입력, 5단계 중 하나. 각 단계는 전문 용어("활동계수 1.375" 같은 숫자)가 아니라
  일상어 설명으로 표시한다(예: "거의 운동을 안 함(주로 앉아서 생활)" ~ "매우 활발함(매일
  강도 높은 운동/육체노동)" 사이 5단계). 정확한 단계 구성과 각 단계의 활동계수 값은 Formula
  Analyst가 1차 출처로 확정한다.
- 입력이 바뀌면 기존 결과를 숨긴다.

### 핵심 결과 — BMR

- BMR을 kcal/일 단위 정수로 표시한다(정확한 반올림 규칙은 `docs/CALCULATOR_RULES.md` 기준으로
  Formula Analyst가 정한다).
- 입력한 성별·나이·키·체중을 결과 상세에 함께 표시한다.
- 계산식에 실제 입력값을 대입한 breakdown을 표시한다.
- 적용한 공식명을 계산 근거 섹션에 명시한다(메인 결과 타이틀에는 노출하지 않음).

### TDEE 섹션 (활동량을 선택한 경우에만 추가로 표시)

- BMR 결과와 명확히 구분된 별도 섹션/카드로 표시한다(같은 숫자처럼 섞어 보여주지 않음).
- TDEE = BMR × 선택한 활동계수를 kcal/일 단위 정수로 표시한다.
- 선택한 활동량 단계를 함께 표시한다.
- 활동량을 선택하지 않아도 BMR 결과는 항상 보여준다(TDEE 섹션만 숨김).

### 결과 안내

- BMR/TDEE는 공식으로 추정한 값이며 실제 대사량과 차이가 있을 수 있다고 안내한다.
- 질병(갑상선 질환 등), 임신·수유, 특수 신체 조건(근육량이 매우 많거나 적은 경우)에서는 오차가
  커질 수 있어 의료진 상담이 필요하다고 안내한다.
- 이 결과가 식단·운동 처방이나 질병 진단이 아니라고 안내한다.

### 공유·공통 UI

- 공통 `ShareActions`를 계산 전·후 동일 위치에 사용한다.
- 결과 공유 상태에는 성별, 나이, 키, 체중, (선택한 경우) 활동량만 저장한다.
- 공유 URL 복원 시 동일한 검증을 통과한 경우에만 자동 계산한다.
- 공통 화면 순서(`docs/DESIGN_SYSTEM.md` "공통 화면 순서")를 따른다: 입력 → 결과 → 계산
  근거 → 소개·사용 방법 → 계산 전제/주의사항 안내 → FAQ.
- 모바일 320px부터 가로 스크롤 없이 동작하고, 결과 갱신 영역에 `aria-live="polite"`를
  적용한다.
- Reset(초기화)과 Sample(샘플 값 채우기)을 제공한다.

## Should Have

- 대표 공식이 아닌 다른 공식(예: 대표 공식이 Mifflin-St Jeor라면 Harris-Benedict)의 결과값을
  참고용 보조 정보로 계산 근거 섹션에 함께 표시(추가 입력 불필요).
- BMR 대비 TDEE가 활동계수별로 어떻게 달라지는지 5단계 전체를 참고 표로 보여주는 기능(현재
  선택한 단계만이 아니라 전체 스케일 비교).

## Could Have (v1 범위 제외)

- 체지방률 기반 Katch-McArdle 공식(체지방률 추가 입력 필요).
- 공식을 직접 선택할 수 있는 고급 옵션(전문가/헬스 트레이너 등 숙련 사용자용).
- 소아·청소년 전용 BMR 공식.
- 결과 인쇄/이미지 저장.

## 범위 밖

- 목표 체중 감량/증량을 위한 칼로리 적자·잉여 계산, 탄단지 매크로 분배, 감량 기간 추천 —
  BMR/TDEE와 계산 로직·검색 의도가 다른 별개 주제라 이 계산기에 포함하지 않는다. 필요하면
  별도 "다이어트 칼로리 계산기"로 차후 신규 제안하되, 지금 이 SPEC의 범위는 아니다.
- 별도의 "TDEE 계산기"/"활동대사량 계산기" 페이지 신설 — 위 "TDEE 포함 여부" 판단에 따라 이
  계산기의 Must Have 섹션으로 이미 다루므로, 같은 입력(성별·나이·키·체중)을 다시 받는 별도
  페이지를 만들지 않는다(`docs/PRODUCT.md` "계산기 중복 금지").
- 체지방률 계산 자체.
- 질병 진단, 식단표·운동 처방.
- 임신부·수유부 전용 보정 공식.
- 사용자의 성별을 외모나 이름으로 추정하는 기능.

## 성공 지표와 완료 기준

- 대표 공식의 성별 상수 적용 오류 0건.
- 활동계수 5단계 매핑 오류 0건(선택한 단계와 곱해지는 계수가 항상 일치).
- BMR만 있고 활동량 미선택 시 TDEE 섹션이 나타나지 않는 케이스 검증.
- kcal 반올림 규칙 전체 결과에서 일관성 100%.
- Golden Test 20개 이상.
- Critical·High 정확성 및 의료 오해 문구 결함 0건.
