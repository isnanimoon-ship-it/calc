# SPEC: 주휴수당 계산기

## 목적
아르바이트·시간제 근로자가 시급과 주 근무시간만 입력하면, 근로기준법상 주휴수당(1주치 금액, 월 환산액, 주휴수당을 포함한 총 급여)과 그 산출 근거를 노무 지식 없이 스스로 확인할 수 있게 한다. "알바 주휴수당", "주휴수당 계산" 검색 의도에 대응하는 참고용 도구이며, 실제 지급 여부에 대한 법적 판정 도구가 아니다.

## 설계상 핵심 결정 — 지급요건으로 게이팅하지 않는다
주휴수당은 (1) 1주 소정근로시간 15시간 이상, (2) 1주간 소정근로일 개근이라는 두 요건을 모두 충족해야 발생한다. 이 계산기는 그 요건 충족 여부를 자동으로 판정해 결과를 막지 않는다.

- 개근 여부(지각·조퇴·결근 실태)는 사용자만 알 수 있고, 15시간 경계도 주별로 달라질 수 있으며, 이 계산기는 "요건을 충족한다고 가정했을 때 금액이 얼마인가"를 보여주는 참고 도구다.
- 따라서 unemployment-benefit SPEC v2의 "게이팅 없이 항상 계산, 전제는 고지" 방식을 그대로 따른다 — 체크박스·관문 없이 항상 계산 결과를 보여주고, 지급요건은 결과 화면·정책 안내의 고지 문구로만 알린다.
- 단, 입력한 주 근무시간이 15시간 미만인 경우에는 결과 화면에 "실제로는 주휴수당이 발생하지 않는다"는 맥락 경고를 눈에 띄게 표시한다(계산 자체는 계속 보여준다). 구체적 시각 처리는 Builder 재량이되 docs/DESIGN_SYSTEM.md "경고/미충족 카드" 패턴을 참고한다.

## 계산기 중복 금지 검토
주휴수당 계산기는 기존 severance-pay(퇴직 시 평균임금 기반 일시금), unemployment-benefit(이직 후 구직급여)와 계산 로직·법조문·검색 의도가 모두 무관하다. 향후 예상되는 "최저임금 계산기"는 고시 최저임금 준수 여부 판정과 최저임금 기준 월 환산액이 주목적이고, "연장근로수당 계산기"는 1일 8시간·주 40시간을 초과한 근로에 대한 가산(근로기준법 제56조)이 주목적이다. 주휴수당 계산기는 사용자가 입력한 시급과 주 근무시간으로 유급주휴일분(근로기준법 제55조)을 분해·환산하는 것이 핵심이라 계산 로직이 다르다. 최저임금 계산기가 "주휴 포함 최저 월급"을 다룰 경우 일부 결과가 겹칠 수 있으나, 그때도 주휴수당 계산기는 "임의 시급 입력 + 주휴분 분해"에, 최저임금 계산기는 "고시값 준수 판정"에 특화되어 검색 의도가 분리된다. 중복 페이지가 아니다.

## Must Have
- **입력 모델: 시급 + 주 소정근로시간(주 근무시간) 두 값만.** 입력 필드 수를 최소화한다(docs/DESIGN_SYSTEM.md "입력 필드 수는 최소화"). 월급 입력 모드는 v1 범위 밖(Could Have 참고). 주 사용자 대상은 아르바이트·시간제 근로자다.
- **입력 라벨·순서**: docs/DESIGN_SYSTEM.md "입력 라벨·순서" 규칙을 따른다.
  - 라벨은 일반 사용자 표현으로 쓴다(예: "시급", "주 근무시간"). "소정근로시간" 등 법령 용어는 라벨이 아니라 helpText에 넣는다(예: helpText "근로계약서상 1주 소정근로시간이며, 휴게시간은 제외합니다").
  - 시급 helpText는 세금 공제 전 시간당 임금임을 짧게 안내한다.
  - 같은 개념은 입력·결과·오류 메시지 전체에서 한 용어로 통일한다.
  - 구체적 입력 필드 설계(입력 방식, placeholder, step, 단위 표기 위치 등) 확정은 Architect/Builder에 위임한다.
- **결과 값 3종을 모두 보여준다**:
  (a) 1주치 주휴수당,
  (b) 월 환산액(월 평균 주 수 기준 — 정확한 환산 계수는 Formula Analyst가 FORMULA.md에서 확정, 통상 4.345주),
  (c) 주휴수당을 포함한 총 급여(주급 기준 및/또는 월급 기준).
- **핵심 결과 카드 권고**: (a) 1주치 주휴수당을 핵심 결과 카드(강조 카드, 계산기당 하나)에 둘 것을 권고한다 — 가장 직접적인 답이고 월 환산 근사 계수에 의존하지 않아 정확하며 "주휴수당"이라는 말 그대로의 값이다. (b)와 (c)는 계산 근거(breakdown)에 배치한다. 다만 사용자 조사에서 "한 달에 얼마"가 더 중요하다고 판단되면 Builder가 (b)를 핵심 카드로 올릴 수 있다(핵심 카드는 항상 하나).
- **지급요건 안내 문구(항상 노출)**: 요건 충족 여부와 무관하게 결과 화면 또는 정책 안내 영역에 아래를 항상 표시한다.
  - "주 소정근로시간이 15시간 미만이면 주휴수당 지급 대상이 아니다"
  - "1주간 소정근로일을 개근해야 주휴수당이 발생한다"
  - 근거 법령명(근로기준법 제55조 등 — 정확한 조문·시행령은 Formula Analyst 확정)
- **결과 화면 breakdown**: docs/DESIGN_SYSTEM.md 공통 화면 순서(입력 → 결과 → 계산 근거 → 정책 안내)를 따라, 1주치 주휴수당 산출 과정(주휴 시간 산정 → 시급 곱셈), 월 환산 과정(× 환산 계수), 총 급여 합산 과정을 단계별 수식과 실제 숫자로 노출한다.
  - 표현 방식은 unemployment-benefit SPEC v2 "계산 근거 화면 표현 원칙"을 따른다: 서술형 내레이션("~해야 하며 ~해서 계산을 진행합니다")이나 내부 구현 설명(반올림·정밀도 처리)을 넣지 않고, "라벨 = 값" 형태의 수식·숫자 위주로 간결하게 쓴다. severance-pay의 수식 표기 스타일을 기준으로 삼는다.
- **정책 고지 문구(정책형 계산기, docs/CALCULATOR_RULES.md "정책형 계산기")**: 결과 화면에 최소한 기준 연도와 "관련 수치(최저임금 등)는 매년 갱신될 수 있다"는 취지를 표시한다. 마지막 검토일·다음 재검토 예정일은 FORMULA.md에서 관리하고 결과 화면 노출은 최소화한다.
- **입력 오류/극단값 방어**: 시급·주 근무시간의 빈 값, 0, 음수, 숫자 아닌 문자열, 비현실적으로 큰 값(예: 주 근무시간이 168시간을 초과) 등 잘못된 입력에 대해 계산을 진행하지 않고 명확한 오류 안내를 표시한다. 시급의 소수점 입력, 주 근무시간의 소수점 입력 허용 여부는 Architect가 결정한다.
- **"사용 안내" 섹션**: docs/ARCHITECTURE.md 페이지 구조의 "사용 방법" 단계에 해당하는 섹션을 `UsageGuide`로 추가한다. 어떤 값을 어떻게 입력하면 되는지 짧게 설명한다(예: "시급과 1주 근무시간을 입력하면 주휴수당을 자동 계산합니다"). 구체적 문구는 Builder 재량.
- **소개 콘텐츠 + FAQ 섹션**: "주휴수당이란 무엇인가요?" 류의 짧은 소개(`IntroSection`)와 FAQ(`FaqAccordion`)를 추가한다. 질문만 아래에 정의하고, 답변 내용은 새로운 법적 주장이 포함되므로 Formula Analyst가 FORMULA.md에서 근거를 확인한 뒤 작성한다.
  1. 주휴수당은 어떻게 계산되나요? (계산 로직 직결)
  2. 주 15시간 미만으로 일하면 주휴수당을 받을 수 없나요? (지급요건, 로직 직결)
  3. 지각·조퇴·결근을 하면 주휴수당은 어떻게 되나요? (개근 요건)
  4. 5인 미만 사업장에서도 주휴수당을 받을 수 있나요? (적용 범위 — Formula Analyst 확인 필요)
  5. 주 40시간을 넘게 일하면 주휴수당도 그만큼 늘어나나요? (40시간 초과분 처리, 로직 직결)
  6. 월급제인데 급여에 주휴수당이 포함되어 있나요? — **이 계산기 범위 밖(포괄임금·월급제 계약 분해는 다루지 않음)이므로 금액을 분해해 제시하지 않는다.** 답변은 "이 계산기는 시급 기준으로 주휴수당을 별도 산출하며, 월급제 계약에 주휴수당이 포함되어 있는지는 근로계약서·급여명세서로 확인해야 한다"는 안내로 한정한다. 질문 자체는 실제 검색 의도와 일치하므로 FAQ에서 제외하지 않는다.
  - 위 1·2·3·5번은 Must Have 계산 로직과 직결되어 Formula Analyst가 FORMULA.md 작성 시 근거를 확인할 항목이므로 중복 조사를 피하고 FORMULA.md 근거를 재사용한다. 4·6번은 별도 확인/안내 범위다.
- **결과 화면 카피 톤**: "계산이 진행되었습니다" 류의 수동적·대행 어투를 피하고 "계산합니다" 같은 확정적·직접적 어투를 쓴다(severance-pay SPEC v2와 동일). 구체적 문구는 Builder 재량.
- **디자인: 카드/시각적 계층**: "사용 안내"와 "계산 근거" 섹션은 텍스트를 단순 나열하지 않고 카드 구분·아이콘·단계 표시 등으로 시각적 계층을 갖춘다. 구체적 디자인은 Architect/Builder 재량이며 docs/DESIGN_SYSTEM.md 기준을 따른다.
- **Reset / Sample**: 초기화 기능을 제공하고, FORMULA.md 검증 예제 값을 그대로 샘플 값으로 사용한다(샘플 자체가 "이 값을 넣으면 이 결과" 검증이 되도록).

## Should Have
- **최저임금 미만 시급 입력 시 참고 경고**: 입력한 시급이 해당 연도 최저임금(`src/data/rates-2026.json`의 `minimumWage.hourly`, 2026년 시간당 10,320원) 미만이면 결과 화면에 참고 경고를 표시한다. 계산을 막지 않는 비차단(non-blocking) 안내이며(게이팅 없음 원칙과 일관), 기준 연도를 함께 표기한다(예: "입력한 시급이 2026년 최저임금 시간당 10,320원보다 낮습니다"). 수습 기간 감액 등 최저임금 예외를 안내 문구에 포함할지는 Formula Analyst가 판단한다. 값은 반드시 데이터 파일에서 가져오고 계산기 코드에 하드코딩하지 않는다.
- **주휴수당 포함 실질 시급 표시**: 주휴수당을 포함했을 때 시간당 환산 임금(실질 시급)을 계산 근거에 함께 보여준다 — "주휴 포함하면 시급이 실제로 얼마인지" 궁금해하는 사용자 의도에 대응한다. 핵심 카드가 아니라 breakdown 항목으로 둔다.

## Could Have (v1 범위 제외)
- 월급 기준 입력 모드(월급 → 시급 역산)
- 포괄임금제(주휴수당 포함 계약)의 분해 — 계약서상 월급에서 주휴수당분이 얼마인지 역산
- 지각·조퇴·결근이 개근 판정에 미치는 영향의 자동 계산
- 연차·공휴일이 낀 주의 특수 처리
- 격주·교대 근무처럼 주별 소정근로시간이 다른 경우(주별 개별 입력)
- 4대보험·세금 공제 후 실수령액
- 여러 사업장 근무시간 합산

## 범위 밖
(의도적으로 구현하지 않는 것)
- **계산 공식·수치·법령 조항의 정의·검증**: 비례 계산식((주 소정근로시간 ÷ 40) × 8 × 시급 등), 40시간 초과분 처리, 월 환산 계수(4.345주 등), 5인 미만 사업장 적용 여부, 단시간·초단시간 근로자 정의, 반올림/절사 정책, 근로기준법 제55조·시행령 제30조 등 조문 확정 — 전부 Formula Analyst 단계(FORMULA.md)의 책임이다. Product Owner는 정의하지 않는다.
- **정책형 계산기 기준값 관리**: 기준 연도, 기준일, 공식 출처, 마지막 검토일, 다음 재검토 예정일의 실제 값은 FORMULA.md(및 `src/data/rates-{year}.json`)에서 Formula Analyst가 관리한다.
- **개근 여부 자동 판정**: 사용자가 소정근로일을 개근했다고 가정하고 계산하며, 지각·조퇴·결근을 입력받아 개근 여부를 판정하지 않는다. 요건은 고지 문구로만 알린다.
- **통상시급과 최저시급의 구분·통상임금 산정**: 입력은 단일 "시급" 하나다. 각종 수당의 통상임금 포함 여부를 따져 통상시급을 산정하는 기능은 다루지 않는다 — 사용자가 자신의 시급을 직접 입력한다.
- **세금·4대보험**: 소득세, 4대보험료 공제 후 실수령액은 다루지 않는다.
- **월급제 계약의 주휴수당 포함분 역산**: FAQ 6번에서 질문은 남기되 금액 분해는 하지 않고 안내로 대체한다.
- **관련 도구(다른 계산기) 링크**: 이번 라운드에서는 타 계산기로의 "관련 도구" 링크를 추가하지 않는다(기존 계산기 SPEC과 동일한 이유 — 사이트 내 계산기 수가 충분히 확보되면 별도 라운드에서 검토).
