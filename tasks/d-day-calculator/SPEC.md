# SPEC: 디데이 계산기

## 목적

특정 날짜를 기다리거나 계획하는 사용자가 계산법을 몰라도 (1) 오늘 또는 임의의 시작일로부터
목표일까지/목표일로부터 며칠이 지났는지를 `D-N`/`D-Day`/`D+N`으로 바로 확인하고, (2) 기준일에
며칠을 더하거나 뺀 날짜가 정확히 몇 년 몇 월 며칠(무슨 요일)인지 바로 확인할 수 있게 한다.

이 계산기는 주말·공휴일을 제외한 "근무일"을 세는 것이 아니라, 모든 날짜를 그대로 세는 순수
달력일(calendar day) 계산기다 — 아래 "계산기 중복 금지 검토" 참고.

## 주요 사용자

- 시험일·시술일·결혼식·여행 출발일 등 특정 날짜를 손꼽아 기다리는 사용자
- 전역일·계약 만료일 등 특정 날짜로부터 며칠이 지났는지 확인하려는 사용자
- "오늘부터 100일 뒤가 며칠인지" 등 기준일에서 며칠 뒤/전 날짜를 알고 싶은 사용자
- 과거의 임의의 두 날짜(예: 만난 날과 헤어진 날) 사이의 날짜 차이를 확인하려는 사용자
- 계산법(날짜 차이, 요일 계산)을 몰라도 결과만 바로 확인하고 싶은 일반 사용자

## 핵심 사용자 흐름

한 화면에서 두 모드를 탭(또는 세그먼트 토글)으로 분리한다(`tasks/business-days/SPEC.md`의
"모드 A/모드 B" 분리 패턴을 그대로 따른다). 두 모드는 입력 형태와 결과 형태가 근본적으로
달라(모드 A는 "두 날짜 → 차이", 모드 B는 "한 날짜 + 일수 → 다른 날짜") 하나의 폼으로
합치면 어떤 필드가 어떤 모드에 쓰이는지 사용자가 혼동하기 쉽다. 모드를 전환해도 각 모드의
입력·결과는 서로 독립적으로 유지해 이전 계산 결과를 잃지 않게 한다.

### 모드 A: 디데이 계산

1. `디데이 계산` 모드를 선택한다(기본 모드).
2. 시작일을 확인한다 — 기본값은 오늘이며, 필요하면 다른 날짜로 바꿀 수 있다.
3. 목표일(기다리거나 기록하려는 날짜)을 입력한다.
4. 계산 버튼을 누른다.
5. `D-N`/`D-Day`/`D+N` 표기와 문장형 설명("OOOO년 O월 O일까지 N일 남았습니다" 등)을 확인한다.
6. 계산 근거(시작일·목표일과 날짜 차이 계산식)를 확인한다.

### 모드 B: 날짜 계산(더하기/빼기)

1. `날짜 계산` 모드를 선택한다.
2. 기준일을 확인한다 — 기본값은 오늘이며, 필요하면 다른 날짜로 바꿀 수 있다.
3. 더하거나 뺄 일수를 입력하고, `더하기`/`빼기` 방향을 선택한다.
4. 계산 버튼을 누른다.
5. 계산된 날짜(`YYYY년 M월 D일`)와 요일을 확인한다.
6. 계산 근거(`기준일 ± N일 = 결과일` 실제 수치 대입 수식)를 확인한다.

## 계산기 중복 금지 검토 (영업일 계산기와의 차이)

`docs/PRODUCT.md` "계산기 중복 금지" 기준(계산 로직이 실질적으로 다른가 / 검색 의도가 실제로
분리되는가)에 따라 `tasks/business-days/SPEC.md`(영업일 계산기)와 대조한 근거를 남긴다.

- **계산 로직이 다르다.** 영업일 계산기는 두 날짜 사이 또는 기준일 전후의 날짜를 셀 때
  토요일·일요일·대한민국 공휴일·사용자 지정 휴무일을 제외한 "영업일(근무일)"만 센다(대체공휴일
  규칙 엔진, 공식 공휴일 데이터 스냅샷 등 별도 정책 데이터에 의존). 반면 이 계산기는 그런
  제외 규칙이 전혀 없는 순수 달력일 차이만 계산한다 — 정책 데이터나 공휴일 판정 로직에
  의존하지 않는다. 같은 두 날짜를 넣어도 두 계산기의 결과 값은 이미 로직 단계에서 달라진다
  (예: 주말이 낀 기간이면 영업일 수 < 달력일 수).
- **검색 의도가 다르다.** 영업일 계산기의 주 사용자는 프로젝트·계약·납품 일정처럼 "근무일
  기준으로 며칠 걸리는지/언제까지인지"를 확인하려는 업무 맥락 사용자다. 이 계산기의 주
  사용자는 시험·결혼식·전역·여행처럼 "실제 달력상 며칠 남았는지/지났는지"를 확인하려는 개인
  이벤트·기념일 카운트다운 맥락 사용자다. "디데이", "디데이 계산기", "날짜 계산기", "며칠
  남았지" 같은 검색어는 "영업일", "근무일 계산" 검색어와 다른 의도를 갖는다.
- **결과 표현이 다르다.** 영업일 계산기는 "영업일 수"와 제외된 날짜 상세 내역을 핵심으로
  보여준다. 이 계산기는 `D-N`/`D-Day`/`D+N` 표기와 계산된 날짜(+요일)를 핵심으로 보여주며,
  제외 날짜 개념 자체가 없다.
- 따라서 두 계산기는 얇은 중복 페이지가 아니라 서로 다른 사용자 문제를 푸는 별개 계산기다.
  기존 계산기의 옵션으로 흡수하지 않고 신규 계산기로 진행한다.

## 날짜 차이 계산 정의 (fencepost 규칙)

두 날짜 사이의 간격은 항상 **달력상 날짜 자체의 차이(day difference)** 로 정의한다. 시각·
시간대는 계산에 관여하지 않으며(`docs/CALCULATOR_RULES.md` "날짜 계산기" 참고), 두 날짜가
같은 날이면 차이는 0이다. 이는 `tasks/military-discharge-date/SPEC.md`가 "날짜 경계 수"로
정의한 방식, `tasks/age-calculator/SPEC.md`가 "출생일을 0일차로 한 날짜 경계 수"로 정의한
방식과 동일한 원칙이다.

- **모드 A(디데이) 표기 규칙**
  - 목표일 = 시작일 → `D-Day` (차이 0)
  - 목표일이 시작일보다 미래 → `D-N`, 이때 `N = 목표일 − 시작일`(아직 N일 남음)
  - 목표일이 시작일보다 과거 → `D+N`, 이때 `N = 시작일 − 목표일`(N일 지남)
  - 예: 시작일 2026-09-12, 목표일 2026-09-13 → `D-1`. 목표일 2026-09-12 → `D-Day`. 목표일
    2026-09-11 → `D+1`.
- **모드 B(날짜 계산) 규칙**: 결과일 = 기준일에서 정확히 N일을 더하거나 뺀 달력상의 날짜다.
  `기준일 + N일`의 결과가 다음과 같이 "1일 차이"인지 "2일째"인지 헷갈리지 않도록, 여기서도
  같은 날짜 차이 정의를 그대로 적용한다(기준일과 결과일 사이의 날짜 차이는 항상 정확히 N).
- **제공하지 않는 방식(명시적으로 배제)**: 시작일을 1일차로 포함해서 세는 인클루시브 카운트
  (예: "만난 지 100일째"처럼 만난 당일을 1일째로 세는 방식)는 제공하지 않는다. 위 날짜 차이
  방식과 인클루시브 카운트 방식이 동시에 존재하면 하루 차이 혼동이 발생하므로, 이 계산기는
  날짜 차이 방식 하나로 통일한다(아래 "v1 범위 밖" 참고).
- 목표일/시작일, 기준일의 선후관계에는 제약을 두지 않는다 — 목표일이 시작일보다 과거여도
  유효한 입력이며 `D+N`으로 정상 계산한다(영업일 계산기의 "종료일은 시작일보다 빠를 수 없다"
  제약과 달리, 이 계산기는 두 날짜의 순서와 무관하게 항상 계산 가능해야 한다).

## Must Have

### 계산 모드

- `디데이 계산`(모드 A)과 `날짜 계산`(모드 B)을 탭 또는 세그먼트 토글로 명확히 분리한다.
- 모드를 전환하면 해당 모드에 필요한 입력만 표시한다.
- 모드 전환 후에도 각 모드의 입력값과 계산 결과를 서로 보존해 혼동시키지 않는다.

### 모드 A 입력 (디데이 계산)

- **시작일**: 필수 날짜 입력. 기본값은 Asia/Seoul 기준 오늘이며, 사용자가 과거·미래 날짜로
  직접 변경할 수 있다(`docs/DESIGN_SYSTEM.md` "날짜 입력은 시간 순서대로 배치한다" 원칙에
  따라 목표일보다 앞에 배치).
- **목표일**: 필수 날짜 입력. 기다리거나 기록하려는 날짜.
- 시작일과 목표일의 선후관계에는 제약이 없다(위 "날짜 차이 계산 정의" 참고).
- 지원 날짜 범위는 Formula Analyst가 확정한다(아래 "다음 단계에서 확정할 항목" 참고).
- 입력값은 브라우저에서만 처리하며 서버로 전송하거나 저장하지 않는다.

### 모드 A 결과

- **핵심 결과**(강조 카드): `D-N`/`D-Day`/`D+N` 표기를 가장 크게 표시한다.
- 표기 바로 아래 문장형 설명을 병기한다(예: "2026년 12월 25일까지 104일 남았습니다",
  "2026년 1월 1일로부터 254일 지났습니다") — D-day 표기에 익숙하지 않은 사용자도 결과를
  바로 이해할 수 있게 한다(`docs/PRODUCT.md` "계산법을 몰라도 쓸 수 있어야 한다").
- 시작일과 목표일을 요약해 표시한다.
- 시작일이 오늘이면 `오늘` 배지를 표시하고, 오늘이 아니면 실제 시작일을 그대로 노출해 계산
  기준이 오늘이 아님을 명확히 한다(`tasks/military-discharge-date/SPEC.md`의 "오늘을 기준일로
  사용했을 때만 `오늘` 배지 표시" 패턴과 동일).

### 모드 B 입력 (날짜 계산)

- **기준일**: 필수 날짜 입력. 기본값은 Asia/Seoul 기준 오늘이며, 사용자가 변경할 수 있다.
- **일수**: 필수 입력. 0 이상의 정수(`inputMode="numeric"`). 사용자가 부호를 직접 입력하지
  않고, 별도의 `더하기`/`빼기` 방향 토글(실제 라디오 그룹)로 방향을 선택한다 — "0.035처럼
  내부 표현을 직접 입력시키지 않는다"는 `docs/DESIGN_SYSTEM.md` 원칙과 같은 취지로, 사용자가
  "-100"을 직접 타이핑해야 하는 UX를 피한다.
- 방향의 기본값은 `더하기`다.
- 일수의 상한은 Formula Analyst가 확정한다(아래 "다음 단계에서 확정할 항목" 참고).
- 일수 0 입력 시 결과는 기준일과 동일한 날짜를 반환한다(정상 케이스로 처리).

### 모드 B 결과

- **핵심 결과**(강조 카드): 계산된 날짜를 `YYYY년 M월 D일` 형식으로 가장 크게 표시하고,
  요일을 함께 표시한다(예: `2026년 12월 20일 (일)`) — 사용자와 합의된 개선 사항.
- 기준일, 입력한 일수, 방향(더하기/빼기)을 요약해 표시한다.

### 계산 방식 (공통)

- 모드 A(날짜 차이)와 모드 B(날짜 이동)는 수학적으로 서로 역함수 관계(diff / add)다. 같은
  날짜 유틸(순수 함수)을 공유해 구현하고, 두 모드가 서로 다른 계산 결과를 내지 않게 한다
  (예: 모드 B에서 기준일 + N일을 계산한 결과일을 모드 A에 시작일=기준일, 목표일=결과일로
  넣으면 정확히 `D-N`이 나와야 한다).
- 모든 날짜는 `YYYY-MM-DD` 문자열 기반으로 처리해 로컬 자정·UTC 변환에 따른 하루 이동 오차를
  방지한다(`tasks/military-discharge-date/SPEC.md`, `tasks/age-calculator/SPEC.md`와 동일
  원칙).
- 윤년(2월 29일), 월말, 연말·연초(예: 12월 31일 + 1일 = 다음 해 1월 1일) 경계를 정확히
  처리한다.
- 요일은 실제 달력 요일을 계산해 한국어 표기(`월화수목금토일`)로 통일한다.

### 오류와 예외 처리

- 시작일·목표일·기준일 누락, 존재하지 않는 날짜(예: 2월 30일)는 계산하지 않고 해당 입력
  가까이에 오류를 표시한다.
- 지원 날짜 범위를 벗어난 입력은 거부하고 지원 범위를 안내한다.
- 모드 B의 일수 입력에 음수, 소수, 숫자가 아닌 값, 비정상적으로 큰 값이 들어오면 계산하지
  않고 오류를 표시한다(방향은 별도 토글로만 조절하므로 일수 필드 자체는 항상 0 이상 정수만
  허용한다).
- 시작일=목표일(모드 A), 일수=0(모드 B)은 오류가 아니라 정상 결과로 처리한다.

### 접근성·반응형

- 모드 전환은 실제 탭 또는 라디오 그룹으로 구현하고 키보드로 조작할 수 있어야 한다.
- 모드 B의 더하기/빼기 방향은 실제 라디오 그룹으로 구현하며 색상만으로 선택 상태를 구분하지
  않는다.
- 모든 날짜·숫자 입력에 연결된 `label`, 도움말, 오류 메시지를 제공한다.
- 결과 갱신 영역은 `aria-live="polite"`로 감싼다.
- 320px, 375px, 390px, 768px, 1440px에서 페이지 전체 가로 스크롤이 없어야 한다.

### 공통 제품 요건

- `계산하기`, 샘플 값, 초기화 기능을 제공한다. 모드 B 샘플은 사용자 원안("기준일부터 +100일")을
  그대로 반영해 `오늘부터 100일 뒤`를 기본 예시로 채운다.
- `components/calculator/ShareActions.tsx`를 계산 전·후 동일 위치에 사용한다.
- 결과 순서는 입력 → 결과 → 계산 근거 → 소개·사용 방법 → 계산 전제 고지(순수 달력일 계산이며
  영업일·공휴일 제외가 없다는 점, Asia/Seoul 기준이라는 점) → FAQ로 한다
  (`docs/DESIGN_SYSTEM.md` "공통 화면 순서").
- 소개, 사용 방법, FAQ와 `WebApplication`·`FAQPage` 구조화 데이터를 제공한다.
- 계산 로직은 UI와 분리한 순수 함수로 구현하고 모드 A/B가 공유한다.
- `docs/CALCULATOR_RULES.md` 기준에 따라 Golden Test 최소 5개, 전체 날짜·경계값 테스트
  15개 이상을 작성한다(윤년, 월말, 연말·연초, 시작일=목표일, 일수=0 등 포함).

## Should Have

- 모드 A 결과에도 시작일·목표일의 요일을 표시한다 — 사용자와 합의한 모드 B의 요일 표시를
  자연스럽게 확장한 것이며, Must Have로 명시적으로 합의되지 않았으므로 Should Have로 둔다.
- 모드 A의 남은/지난 일수를 주(week) 단위로 환산해 병기한다(예: `D-45 · 6주 3일 후`).
- 모드 B 결과에 오늘 기준 `D-N`/`D-Day`/`D+N` 배지를 함께 표시해 두 모드를 자연스럽게
  연결한다(기준일이 오늘이 아닐 때도 유용).
- 결과 텍스트 복사 및 조건을 포함한 URL 공유.
- 기준일·시작일을 "오늘로 되돌리기" 빠른 버튼.

## Could Have (v1 범위 제외)

- 자주 쓰는 기념일 프리셋(수능, 크리스마스, 설날 등 원클릭 목표일 채우기) — 매년 날짜가
  바뀌는 항목(수능 등)은 연도별 데이터 유지보수 비용이 있어 v1 이후로 미룬다.
- 음력 변환 및 음력 기념일 지원 — `korean-lunar-calendar` 패키지가 이미 다른 계산기
  (`age-calculator`의 띠 계산)에서 의존성으로 쓰이고 있어 재사용 가능성은 있으나, 이 계산기의
  핵심 문제(달력일 D-day, 날짜 더하기/빼기)에는 필수가 아니다.
- 날짜 차이를 달력 기준 `N개월 N일`로 환산해 표시(개월은 월별 일수가 달라 단순 나눗셈보다
  복잡한 계산이 필요하다).
- 결과 공유 이미지 생성, 캘린더 파일(ICS) 다운로드.
- 여러 목표일을 동시에 등록해 비교하는 리스트·대시보드 기능.

## 완료 기준

- `SPEC.md`의 두 핵심 기능(디데이 카운트, 날짜 더하기/빼기)과 `FORMULA.md`의 범위가 정확히
  일치한다.
- 다음 불변식이 성립한다.
  - 모드 A: 시작일=목표일이면 `D-Day`, 목표일이 미래면 `D-N`(N=목표일−시작일), 과거면
    `D+N`(N=시작일−목표일).
  - 모드 B: `기준일 + N일`(더하기) 또는 `기준일 − N일`(빼기)로 계산된 결과일과 기준일 사이의
    날짜 차이는 항상 정확히 N이다.
  - 모드 A와 모드 B는 서로 역함수 관계로 일관된 결과를 낸다(위 "계산 방식" 참고).
- 윤년 2월 29일, 월말, 연말·연초 경계에서 하루 오차가 없다.
- Golden Test 최소 5개, 전체 날짜·경계값 테스트 15개 이상을 통과한다.
- 계산 정확성 감사 33/35 이상, 총점 92점 이상이며 Critical·High 결함이 없어야 공개한다.

- slug: `d-day-calculator`
  - 근거: 사용자가 이미 "디데이 계산기"로 요청했고, "디데이"는 영어 표기가 `D-day`로
    고정된 표현이라 `d-day-calculator`가 산식이 아닌 이름 자체를 그대로 서술한다. 모드
    B(날짜 더하기/빼기)까지 포함하지만, 두 기능 모두 "특정 날짜를 기준으로 한 날짜 계산"이라는
    같은 문제의 두 방향(차이 구하기 / 이동하기)이라 별도 slug로 쪼개지 않는다
    (`tasks/business-days/SPEC.md`가 "기간 계산"과 "전후 계산"을 하나의 `business-days`
    slug로 묶은 선례와 동일).
- title: `디데이 계산기`
- category: `date`
  - 근거: `src/calculators/registry.ts`의 `CalculatorCategory` 정의상 `date`는 "날짜, 나이,
    근속기간 등"이며 `age-calculator`, `business-days`, `military-discharge-date`가 이미
    이 카테고리에 있다. 아이콘도 이 세 계산기가 공유하는 `calendar` 키를 그대로 재사용한다.
  - 중복 확인: `src/calculators/registry.ts` 전수 확인 결과 "디데이", "d-day", "날짜 계산"
    관련 계산기는 없다. `business-days`와의 차이는 위 "계산기 중복 금지 검토"에 근거를
    남겼다.
