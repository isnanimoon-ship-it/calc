## 6. 발견된 이슈

### 6.1 [Low/정보] 월세 음수 검증 메시지는 정상 UI 흐름에서는 도달 불가능하다

`monthlyRent` 입력 필드가 `inputMode="numeric"` + `onChange`에서
`value.replace(/\D/g, "")`로 비숫자 문자를 전부 제거하기 때문에, 사용자가 마이너스
기호를 타이핑해도 즉시 제거되어 필드에 음수가 입력될 수 없다. 따라서
`validation.ts`의 "월세는 음수를 입력할 수 없습니다." 오류 메시지는 일반적인 마우스/
키보드 입력으로는 트리거할 수 없다(공유 URL을 직접 조작하는 등 비정상 경로로만
도달 가능 — 아래 6.2 참고). 다만 이는 매매가격·보증금 필드도 동일한 패턴이라
이 계산기만의 결함이 아니라 사이트 전역의 숫자 입력 관례이며, 방어 코드 자체가
있는 것은 바람직하다. **차단 사유 아님, 정보성 기록.**

### 6.2 [Low] 조작된 공유 URL(`?s=...`)에 유효성 검증 실패 값이 있으면 완전히 무음(silent)으로 실패한다

`ui.tsx`의 `useCalculatorShare` 콜백은 `validateRealEstateBrokerageFeeInput`이 실패하면
`if (!validated.success) return;`으로 그냥 아무 것도 하지 않는다. 실제로
`monthlyRent: -500000`을 담은 base64 payload(`deposit: 100,000,000`, 정상적으로는
UI에서 만들 수 없는 값이지만 URL을 직접 편집하면 만들 수 있음)를 넣어 접속해보니,
거래 유형 토글도 선택되지 않고 입력 필드도 전혀 렌더링되지 않는(즉 초기 빈 폼 그대로)
상태로 조용히 대체되었다 — 오류 메시지도, "공유된 값을 불러오지 못했습니다"류의
안내도 없다. 실사용 시나리오에서 발생 확률은 매우 낮다(정상적인 "링크 복사" 버튼은
항상 유효한 상태만 만들어낸다). 다른 계산기들도 동일한 `useCalculatorShare` 패턴을
공유하므로 이 계산기만의 결함이라기보다 사이트 전역 패턴에 가깝다. **차단 사유
아님(Low), 정보성 기록** — 필요 시 향후 라운드에서 `useCalculatorShare` 자체 개선을
검토할 수 있다(이 계산기 범위 밖).

### 6.3 [Low] 320px 폭에서 "임대차(전세·월세)" 토글 버튼 텍스트가 "월세" 단어 중간에서 줄바꿈된다

320px 뷰포트에서 스크린샷으로 실측한 결과, "임대차(전세·월세)" 버튼 텍스트가
"임대차(전세·월" / "세)"로 두 줄에 걸쳐 줄바꿈되어 "월세"라는 단어가 어색하게
쪼개진다. 버튼 자체는 `grid-cols-2`로 "매매" 버튼과 같은 높이로 자동 확장되어
레이아웃이 깨지거나 가로 스크롤이 발생하지는 않는다(정상적으로 세로로만 늘어남).
UX/UI Critic이 재검증 절에서 "320px 등 협소 화면에서 라벨·토글 텍스트 실제 렌더링
확인은 QA 단계 실측이 필요함"으로 명시적으로 위임한 항목인데, 실측 결과 **기능적
손상은 없으나 줄바꿈 지점이 다소 어색함**을 확인했다. 375px 이상에서는 한 줄로
정상 표시된다. **차단 사유 아님(Low, 순수 타이포그래피 다듬기 권고)**.

### 6.4 두 개의 `aria-live="polite"` 영역이 페이지에 공존한다(결함 아님, 기록용)

`ShareActions` 컴포넌트가 공유 피드백용 빈 `<p aria-live="polite">`를 렌더링하고,
결과 영역도 별도로 `<div aria-live="polite">`를 쓴다. 스크린리더 입장에서 두 영역이
독립적으로 동작하므로 문제는 없으나(각각 자기 콘텐츠가 바뀔 때만 알림), 자동화 테스트
작성 시 `document.querySelector('[aria-live="polite"]')`처럼 첫 번째 매치만 가정하면
결과 영역을 놓치기 쉽다는 점을 기록해 둔다. **결함 아님, 정보성.**
