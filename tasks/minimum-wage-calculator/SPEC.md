# SPEC: 최저임금·시급↔월급 계산기

## 목적
시급 또는 월급 중 **하나만** 입력해도 다른 한쪽 금액으로 즉시 환산해 보여주고, 그 금액이 올해(기준 연도) 법정 최저임금 이상인지를 계산법을 몰라도 스스로 확인할 수 있게 한다. "최저시급 얼마", "시급 월급 계산기", "내 월급 최저임금 위반 아닌가" 같은 검색 의도에 대응하는 참고용 도구이며, 실제 최저임금법 위반 여부에 대한 법적 판정 도구가 아니다.

## 주요 사용자
- 시급을 받는 아르바이트생·단시간 근로자가 "이 시급이면 한 달에 얼마 받는지" 확인하려는 경우
- 월급제 근로자가 "내 월급을 시급으로 따지면 얼마인지, 최저임금보다 높은지" 확인하려는 경우
- 채용 공고의 시급/월급 표기가 올해 최저임금 기준을 충족하는지 빠르게 검산하려는 구직자·소상공인 사업주
- "올해 최저임금이 정확히 얼마인지" 자체를 찾아보러 온 사용자(시급/월 환산액 조회)

## 계산기 중복 금지 검토

### weekly-holiday-allowance(주휴수당 계산기)와의 관계 — 이미 사전 합의된 차별점
`tasks/weekly-holiday-allowance/SPEC.md`는 이 계산기를 만들 때를 미리 대비해 다음과 같이 차별점을 명시해 두었다(원문 인용):

> 향후 예상되는 "최저임금 계산기"는 고시 최저임금 준수 여부 판정과 최저임금 기준 월 환산액이 주목적이고 ... 최저임금 계산기가 "주휴 포함 최저 월급"을 다룰 경우 일부 결과가 겹칠 수 있으나, 그때도 주휴수당 계산기는 "임의 시급 입력 + 주휴분 분해"에, 최저임금 계산기는 "고시값 준수 판정"에 특화되어 검색 의도가 분리된다. 중복 페이지가 아니다.

이 SPEC은 위 사전 합의를 그대로 이어받아 다음과 같이 역할을 나눈다.

| | weekly-holiday-allowance | minimum-wage-calculator (이 계산기) |
|---|---|---|
| 핵심 질문 | "내 시급·주 근무시간 기준으로 주휴수당이 얼마인가" | "내 시급/월급이 올해 최저임금 기준을 충족하는가, 시급↔월급으로 바꾸면 얼마인가" |
| 산출 초점 | 주휴수당 금액 자체(1주치/월 환산/포함 총급여)의 **상세 분해** | 시급↔월급 **양방향 환산값**과 **최저임금 대비 준수 여부 판정** |
| 최저임금 취급 | Should Have의 비차단 참고 경고 1줄(부가 기능) | Must Have, 화면의 핵심 목적 |
| 방향성 | 시급 → (주휴수당, 총급여) 단방향 | 시급 → 월급 **또는** 월급 → 시급 양방향 |
| 개근·15시간 요건 게이팅 | 다룸(비차단 안내) | 다루지 않음 — 이미 근무 중임을 전제로 "그 임금이 최저임금 이상인가"만 확인 |

- **겹치는 계산 조각**: 두 계산기 모두 "주 근무시간 → 주휴시간 포함 월 환산 시간"이라는 동일한 산식 조각(근로기준법 제55조·최저임금법 시행령 제5조가 각각 다른 목적으로 요구)을 내부적으로 쓸 수 있다. 이는 **계산기 페이지 자체의 중복이 아니라 계산 유틸리티 조각의 중복 가능성**이므로, Architect가 두 계산기 사이에 공유 가능한 순수 함수(예: `weeklyHoursToMonthlyHours`)로 추출할지 검토할 것을 권고한다(Product Owner가 구현 방식을 강제하지는 않는다).
- **이 계산기는 주휴수당 금액 자체를 별도 항목으로 breakdown하지 않는다**(아래 "범위 밖" 참고) — 그렇게 하면 결과 화면이 weekly-holiday-allowance와 사실상 동일해져 중복 위험이 생기므로 의도적으로 제외한다. 주휴시간은 "월 환산 시간을 구성하는 내부 계수"로만 쓰고, 사용자에게는 "월 환산 시간(주휴 포함)" 한 줄로만 노출한다.
- **검색 의도 분리**: "최저임금 계산기"는 연 1회(매년 1월) 검색량이 급증하는 정책 조회성 키워드이고, "주휴수당 계산기"는 근로 형태(아르바이트)에 특화된 키워드다. 네이버/구글 키워드 자체가 다르며 서로 대체재가 아니다.

### four-major-insurance / annual-salary-take-home-pay와의 관계
두 계산기 모두 "월급에서 공제되는 금액"을 다루는 반면, 이 계산기는 공제를 전혀 다루지 않고 **세전 금액 자체가 최저임금 기준을 충족하는지**만 본다. 계산 로직·목적이 명확히 달라 중복이 아니다(범위 밖에서 재확인).

### annual-leave-allowance FORMULA.md의 필드 재사용(승격) 확인
`tasks/annual-leave-allowance/FORMULA.md`는 `src/data/rates-2026.json`의 `minimumWage.hourly.value`, `laborStandards.statutoryDailyHours.value`를 "최저임금 참고 경고"라는 **부가 기능**용으로만 재사용했다. 이 계산기는 그 필드들과 `laborStandards.statutoryWeeklyHours.value`, `laborStandards.monthlyWeekFactor.value`까지 포함해 **주 계산 대상(핵심 산식의 입력값)으로 승격**해서 쓴다. 이 파일들의 주석은 애초에 "향후 추가될 최저임금 관련 계산기도 정확히 같은 값을 쓴다"고 명시하며 이런 재사용을 이미 예정해 두었으므로, 신규 필드를 새로 만들지 않고 기존 최상위 네임스페이스(`minimumWage`, `laborStandards`)를 그대로 참조한다. 다만 "최저임금의 월 환산 고시값(예: 209시간 기준 월 환산액)"이 정부가 시급과 별도로 공식 발표하는 값인지, 아니면 항상 시급 × 월 환산 시간으로 계산기가 직접 산출해야 하는 값인지는 Formula Analyst가 확인해 필요 시 데이터 파일에 새 필드를 추가한다(아래 "정책 데이터 요구사항" 참고).

## Must Have

### 입력 모델 — 양방향 환산을 "모드 전환" 방식으로 다룬다
- **모드 토글 하나로 방향을 정한다**: "시급으로 계산" / "월급으로 계산" 중 하나를 선택하는 세그먼트 컨트롤(또는 라디오)을 둔다. 시급과 월급을 동시에 두 칸 입력받아 서로 맞는지 검증하는 방식은 쓰지 않는다 — docs/DESIGN_SYSTEM.md "입력 필드 수는 최소화" 원칙에 따라, 사용자가 아는 값 하나만 입력하면 나머지는 계산기가 채운다.
  - 시급 모드: 시급을 입력받아 월 환산 급여(주휴시간 포함 월 환산 시간 기준)를 산출한다.
  - 월급 모드: 월급을 입력받아 시급을 역산한다.
  - 두 모드 모두 결과 화면에는 "시급 얼마 / 월급 얼마"를 함께 보여준다 — 어느 모드로 입력했든 사용자는 결국 두 값을 다 확인할 수 있어야 한다. 다만 **어느 값이 사용자가 직접 입력한 값이고 어느 값이 환산(계산)된 값인지는 화면에서 명확히 구분**해 표시한다(예: 입력값은 폼에 그대로 남기고, 환산값에는 "환산" 표시).
- **공통 입력: 주 근무시간(선택, 기본값 40시간)**: 월 환산 시간 계산에 쓰인다. 라벨·helpText는 weekly-holiday-allowance의 "주 근무시간" 패턴(일상어 라벨 + "소정근로시간" 등 법령 용어는 helpText로) 그대로 따른다. 기본값 40시간(법정 기준근로시간)을 미리 채워 두어, 표준 근로자는 이 필드를 건드리지 않고도 바로 계산할 수 있게 한다.
- 입력 필드 수: 모드 토글 + 금액 1개 + 주 근무시간 1개(기본값 있음) = 사실상 필수 입력 1개로 최소화한다.

### 최저임금 비교 판정 (이 계산기의 핵심 목적)
- 입력·환산된 **시급**과 **월급** 양쪽 모두를 해당 연도 고시 최저임금과 비교해 "최저임금 이상" / "최저임금 미만" 참고 판정을 항상 보여준다.
- **게이팅하지 않는다**: weekly-holiday-allowance·unemployment-benefit이 확립한 "게이팅 없이 항상 계산, 판정은 결과 화면의 비차단 안내로만 전달" 원칙을 그대로 따른다. 최저임금 미만이어도 계산 자체를 막지 않고, 눈에 띄는 방식(docs/DESIGN_SYSTEM.md "경고/미충족 카드")으로 안내한다.
- 기준 연도를 항상 함께 표기한다(예: "2026년 최저임금 시간당 10,320원 기준"). 값은 반드시 `src/data/rates-{year}.json`에서 가져오고 계산기 코드에 하드코딩하지 않는다.
- **월급 비교 시 산정 기준 명시**: 월급을 최저임금과 비교하려면 "월 환산 시간"이 필요하다(시급 하나만으로는 월급의 적정성을 알 수 없음). 이 월 환산 시간이 정확히 어떤 산식(주휴시간 포함 여부, 209시간 등 관행값 사용 여부)을 따를지는 Formula Analyst가 최저임금법 시행령 등 1차 출처로 확정한다 — Product Owner는 "월 환산 시간이라는 개념 자체를 반드시 화면에 명시하고, 그 값이 어디서 왔는지 계산 근거에서 보여줘야 한다"는 요건만 못박는다.

### 최저임금 산입범위 — v1은 단순화한다
- **Must Have 범위**: 사용자가 입력한 시급 또는 월급 **총액**을 그대로 최저임금 비교 대상으로 삼는다. 기본급·정기상여금·복리후생비 등 항목별로 최저임금 산입 여부를 나누어 판정하지 않는다.
- 결과 화면(또는 정책 안내 영역)에 다음 취지의 고지 문구를 상시 노출한다: "이 계산기는 입력한 금액 전체를 기준으로 비교하며, 실제 최저임금법상 임금 항목별 산입 여부(상여금·복리후생비 등)는 따지지 않습니다. 급여명세서상 항목 구성에 따라 실제 최저임금 준수 여부가 달라질 수 있습니다."
- 이 단순화 자체가 사용자에게 잘못된 안심을 줄 위험이 있음을 인지하고, 문구는 결과 화면에서 눈에 띄게(작은 각주가 아니라 정책 안내 카드 수준으로) 배치한다.
- 산입범위 세부 판정(항목별 입력, 연도별 산입비율 이력 등)은 Could Have로 분리한다(아래 참고).

### 결과 화면 breakdown
- docs/DESIGN_SYSTEM.md 공통 화면 순서(입력 → 결과 → 계산 근거 → 소개/사용법 → 정책 안내 → FAQ)를 따른다.
- **핵심 결과 카드(강조, 계산기당 하나)**: 환산된 값(사용자가 입력하지 않은 쪽)과 최저임금 준수 여부 배지를 함께 둔다. 예: 시급 모드로 계산했다면 "월 환산 급여" + "최저임금 이상/미만" 배지가 핵심 카드.
- **계산 근거(breakdown)**: (1) 입력값, (2) 월 환산 시간 산출 과정(주 근무시간 → 월 환산 시간, 사용한 계수 명시), (3) 환산된 시급/월급 산출식, (4) 최저임금과의 비교식(각각 시급 대 시급, 월급 대 월 환산 최저임금)을 "라벨 = 값" 형태로 단계별로 노출한다(서술형 내레이션 금지, severance-pay·weekly-holiday-allowance 표기 스타일 준수).
- 올해 최저임금 자체(시급·월 환산액)를 결과 화면 어딘가에 명시적으로 표시해, 별도로 "최저임금이 얼마인지"만 알고 싶은 사용자의 조회 의도도 함께 충족한다.

### 정책 고지 (정책형 계산기, docs/CALCULATOR_RULES.md "정책형 계산기")
- 기준 연도와 "매년 갱신될 수 있다"는 취지를 결과 화면에 표시한다.
- 최저임금 산입범위 단순화 고지(위 항목)를 포함한다.
- 마지막 검토일·다음 재검토 예정일은 FORMULA.md에서 관리한다.

### 입력 오류/극단값 방어
- 시급·월급·주 근무시간의 빈 값, 0, 음수, 숫자 아닌 문자열, 비현실적으로 큰 값을 계산하지 않고 명확한 오류로 안내한다.
- 주 근무시간은 0 초과 168시간(주 최대 시간) 이하로 제한한다(weekly-holiday-allowance와 동일한 판단 기준 재사용).
- 시급·월급의 소수점 입력 허용 여부는 Architect가 결정한다.

  3. 왜 월급을 시급으로 계산할 때 주휴시간을 포함하나요? (월 환산 시간에 주휴시간이 왜 들어가는지 — 최저임금법 시행령 근거, 로직 직결)
  4. 최저임금보다 낮게 받고 있으면 어떻게 해야 하나요? (일반 안내, 법적 조치 유도가 아니라 고용노동부 등 공식 창구 안내 수준으로 한정)
  5. 상여금이나 식대도 최저임금 계산에 포함되나요? (산입범위 — 이 계산기는 단순화했다는 점을 다시 안내)
  6. 수습 기간에는 최저임금보다 적게 받아도 되나요? (최저임금법 제5조 감액 예외 — Should Have 안내와 연결, 로직에는 반영하지 않음을 명시)
  7. 알바생인데 이 계산기로 주휴수당까지 계산할 수 있나요? — **범위 밖**. 답변은 "이 계산기는 시급↔월급 환산과 최저임금 비교만 다루며, 주휴수당 자체의 상세 계산은 별도의 주휴수당 계산기를 이용해 달라"는 안내로 한정한다.
- **카피 톤**: "계산합니다" 같은 확정적 어투를 쓴다(severance-pay·weekly-holiday-allowance와 동일).
- **디자인**: 사용 안내·계산 근거 섹션은 카드 구분·단계 표시 등 시각적 계층을 갖춘다(구체 디자인은 Architect/Builder 재량).

## Should Have
- **최근 N년(예: 5년) 최저임금 추이 표/그래프**: 과거 연도 최저임금 값을 추가 데이터로 구축해야 하므로 v1 필수는 아니다. 데이터 확보 여부는 Formula Analyst가 판단한다.
- **수습 기간 감액 참고 안내**: 최저임금법 제5조에 따라 1년 이상 근로계약을 체결한 근로자를 수습 사용 중인 경우 3개월 이내에서 최대 10% 감액 가능하다는 점을 안내 문구로만 제공한다(계산에 자동 반영하지 않음 — 계약 기간·직종 등 판단이 필요해 자동화하면 오판 위험이 큼).
- **산입범위 항목별 입력**: 기본급/정기상여금/복리후생비 등을 나눠 입력받아 항목별 산입 여부를 판정하는 세분화 기능. 최저임금법 시행령 별표 확인이 필요하므로 Formula Analyst 조사 비용이 크다.
- **주휴시간 포함 여부를 사용자가 토글로 확인**: "주휴시간을 포함한 월 환산 시간" vs "포함하지 않은 단순 근로시간만의 환산"을 나란히 보여줘 차이를 이해시킨다(계산 근거 보강 목적, 주휴수당 금액 자체를 별도 분해하는 것은 아님).
- **공유 기능**: `ShareActions`를 이용한 결과 공유.
- **소개/FAQ 구조화 데이터**(`WebApplication`·`FAQPage`).

## Could Have (v1 범위 제외)
- 최저임금 산입범위의 완전 자동 판정(연도별 산입비율 이력 포함 — 2024년 전면 산입 완료 이전 연도까지 다루는 기능)
- 연령·특수직종(청소년, 감시·단속적 근로자 등)별 최저임금 예외 적용 여부 자동 판정
- 여러 근로자의 임금을 일괄 검산하는 사업주 모드
- 해외/타 지역 최저임금과의 비교
- 세전 금액 기준 4대보험·세금 공제 후 실수령액 계산(다른 계산기 영역)
- 주휴수당 금액 자체의 상세 breakdown(weekly-holiday-allowance 영역)

## 범위 밖
(의도적으로 구현하지 않는 것)
- **최저임금법 위반 여부의 법적 판정**: 이 계산기는 참고용 비교 도구이며, 실제 위반 여부·구제 절차는 고용노동부·노동위원회 등 공식 절차로 확인해야 함을 고지한다.
- **최저임금 산입범위 세부 법적 판정**: 임금 항목별(상여금, 복리후생비, 각종 수당) 산입 여부·연도별 산입비율 이력은 다루지 않는다. 입력한 총액을 그대로 비교한다(위 "산입범위 — v1은 단순화한다" 참고).
- **지급요건(15시간 이상, 개근 등) 판정**: 이미 근무 중임을 전제로 하며, weekly-holiday-allowance가 다루는 주휴수당 지급요건 게이팅은 이 계산기의 관심사가 아니다.
- **주휴수당 금액 자체의 상세 산출(1주치 금액 등)**: weekly-holiday-allowance 영역이다. 이 계산기는 월 환산 시간을 구성하는 내부 계수로만 주휴시간을 쓴다.
- **4대보험·세금 공제 후 실수령액**: `annual-salary-take-home-pay`, `four-major-insurance` 영역이며 합치지 않는다.
- **연봉 단위 입력/환산**: 이 계산기는 시급↔월급 양방향만 다루며 연봉 입력은 받지 않는다(연봉 환산이 필요하면 `annual-salary-take-home-pay`를 이용하도록 안내).
- **수습 감액의 자동 계산 반영**: Should Have의 "안내"로만 다루고, 계산 로직에 자동으로 10% 감액을 적용하지 않는다.
- **관련 도구(다른 계산기) 링크**: 이번 라운드에서는 추가하지 않는다(기존 계산기 SPEC들과 동일한 판단).

## 정책 데이터 요구사항
`FORMULA.md` 단계에서 각 값의 공식 출처, 시행일, 확인일, 다음 재검토일을 재확인하고 정책 데이터로 관리한다.
- `src/data/rates-2026.json`의 `minimumWage.hourly.value`(시급), `laborStandards.statutoryWeeklyHours.value`(40시간), `laborStandards.statutoryDailyHours.value`(8시간), `laborStandards.monthlyWeekFactor.value`(월 환산 계수) — 기존 최상위 필드를 신규 생성 없이 그대로 재사용한다(위 "annual-leave-allowance FORMULA.md의 필드 재사용" 참고).
- **월 환산 최저임금(고시 월 환산액)**이 정부가 시급과 별도로 공식 발표하는 값인지, 계산기가 시급 × 월 환산 시간으로 직접 산출해야 하는 값인지 Formula Analyst가 1차 출처(최저임금위원회·고용노동부 고시)로 확인한다. 별도 고시값이 존재한다면 `minimumWage` 네임스페이스에 `monthlyEquivalent` 등 필드 추가를 검토한다(신규 필드 추가는 Architect 라운드에서 실제 스키마로 확정).
- 최저임금법 시행령상 "월 환산 시간" 산정 시 주휴시간 포함 여부·구체적 산식의 1차 출처(최저임금법 제5조, 같은 법 시행령 제5조 등)를 확인한다.
- 확정되지 않았거나 공식 원문으로 검증하지 못한 값은 추정해 넣지 않고 "확인 필요"로 남긴다.
