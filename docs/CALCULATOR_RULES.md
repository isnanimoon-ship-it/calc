# 계산기 공통 정확성 규칙

## 정확성 원칙
- 모든 계산 로직은 실제 법령·고시·공식 문서에 근거한다.
- 확실하지 않은 수치는 추정하지 않고 "확인 필요"로 남기고 알린다.
- 계산 함수는 반드시 단위 테스트를 함께 작성한다 (Golden Test 규칙 참고).

## 데이터 파일 스키마
연도별로 바뀌는 수치는 `/src/data/rates-{year}.json`에 분리한다. 항목마다 다음 필드를 통일해서 쓴다 (FORMULA.md의 "기준/출처" 섹션도 동일 필드명을 사용한다 — 문서 간 스키마를 통일해 나중에 재검토 알림 등을 자동화하기 쉽게 한다):
```
{
  value, unit,
  source: { law, article, effectiveDate, url? },
  lastVerified: "YYYY-MM-DD",
  nextReviewDue: "YYYY-MM-DD"   // 정책형 계산기만
}
```
아직 확정되지 않은 고시값은 파일에 넣지 않고 이전 연도 값을 유지하며 "확인 필요" 상태로 별도 표시한다.

## 금액/숫자 연산
- 기본은 원 단위 정수 연산. 부동소수점(`number`)으로 금액을 직접 더하거나 곱하지 않는다.
- 법적으로 "전"(원의 1/100) 단위 정밀도가 필요한 계산(예: 퇴직금 평균임금)은 정수 스케일링(예: 전 단위 정수)으로 처리하고 FORMULA.md에 근거를 남긴다.
- Number / 정수 스케일링 / BigInt / decimal.js·big.js 중 선택은 Architect가 계산기별로 결정한다 (docs/ARCHITECTURE.md 참고). 모든 계산기에 무조건 무거운 decimal 라이브러리를 쓰지 않는다.
- 화면 표시는 `Intl.NumberFormat('ko-KR')` 등으로 통일한다.

## 단위
값과 단위를 혼동하지 않는다. 예: 이율 입력 `5`가 5%인지 0.05인지 내부적으로 명확히 정의한다. UI 입력 표현(%)과 내부 계산 표현(0.05)을 분리한다.

## 반올림 정책
- 중간 계산 단계에서 임의로 반올림하지 않는다. 가능하면 최종 표시 단계에서만 formatting한다.
- 특정 법률/세금 공식에서 단계별 절사가 법적으로 요구되면 FORMULA.md에 명확히 기록한다.
- 계산기마다 버림/올림/반올림/소수 N자리/원 단위/10원 단위/100원 단위 중 무엇을 쓰는지 FORMULA.md에 명시한다.

## 입력 검증 & 예외 처리
- 모든 입력은 타입, 범위, 형식을 검증한다(zod 등). 계산 로직과 함께 관리한다.
- 비정상 입력(음수, 0, 소수점, 비정상적으로 큰 값, 빈 값)에는 명확한 에러 메시지를 노출하고 잘못된 값으로 결과를 보여주지 않는다.
- 계산기 하나의 런타임 에러가 사이트 전체를 죽이지 않도록 계산기 단위 Error Boundary를 적용한다.

## Golden Test
정답이 확정된 테스트를 최소 5개(복잡한 계산기는 10개 이상) 작성한다. Builder 구현 결과와 정확히 일치해야 한다. 공식 계산기(고용노동부, 국세청 홈택스 등) 예시값과 대조한 케이스를 최소 2개 포함한다. 대조 기준(어느 공식 계산기, 언제 확인했는지)을 테스트 파일 주석에 남긴다.

## Edge Case Test
최소 다음을 검토한다: 0, 1, 음수, 소수, 매우 작은 값, 매우 큰 값, 빈 입력, 숫자가 아닌 문자열, 최소값, 최대값, 경계 바로 아래/경계값/경계 바로 위. 계산기 특성상 불가능한 입력은 명확히 validation한다.

## Floating Point
JS의 `0.1 + 0.2` 류 문제가 사용자 결과에 노출되지 않게 한다. 전략 선택은 위 "금액/숫자 연산" 및 docs/ARCHITECTURE.md를 따른다.

## 날짜 계산기
timezone, 윤년, 월별 일수, DST, 시작일/종료일 포함 여부를 주의한다. Date 객체로 인해 날짜가 하루 이동하는 문제가 없는지 검증한다.

## 금융 계산기
연이율/월이율, 단리/복리, 납입주기, 원리금균등/원금균등, 만기일시, 세전/세후를 명확히 구분한다. 서로 다른 계산 방식을 같은 공식으로 처리하지 않는다.

## 정책형 계산기
세금, 연봉, 4대보험, 정부지원금, 부동산 비용 등 정책 의존 계산기는 FORMULA.md에 다음을 반드시 기록한다:
```
기준 연도: YYYY
기준일: YYYY-MM-DD
공식 출처: ...
마지막 검토: YYYY-MM-DD
다음 재검토 예정일: YYYY-MM-DD
```
정책 변경 여부를 알 수 없는 계산기를 영구히 정확한 것처럼 표현하지 않는다 (결과 화면 고지 문구 필수, docs/DESIGN_SYSTEM.md 참고).
