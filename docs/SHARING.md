# 계산기 공유 기능

## 목표

모든 계산기에 동일한 공유 UI를 제공한다. 계산 전에는 계산기 자체를, 계산 후에는 입력 조건과
결과를 다시 열 수 있는 URL을 공유한다. 공유를 위해 입력값을 서버에 저장하지 않는다.

## 기본 채널

| 채널 | 동작 | 비고 |
|---|---|---|
| X | Web Intent 새 창 열기 | 별도 X 앱 키 불필요 |
| 카카오톡 | Kakao JavaScript SDK 어댑터 호출 | 운영 도메인·JavaScript 키 등록 후 활성화 |
| 링크 복사 | 결과 URL을 클립보드에 복사 | 항상 제공하는 최종 fallback |
| 다른 앱 | Web Share API로 OS 공유창 열기 | 지원 브라우저에서만 버튼 표시 |

Facebook·Threads·Telegram·LINE·네이버 밴드는 v1 직접 버튼에 포함하지 않는다. 모바일에서는
`다른 앱` 공유창으로 대부분 접근할 수 있고, 직접 버튼 추가 여부는 실제 공유 통계로 결정한다.

## 상태별 동작

### 계산 전

- canonical 계산기 URL을 공유한다.
- 제목은 계산기 이름, 본문은 기능을 한 문장으로 소개한다.
- 공유 영역 라벨은 `공유`로 표시한다.

### 계산 후

- 같은 위치와 같은 버튼 구성을 유지한다.
- 공유 영역 라벨은 `결과 공유`로 바뀐다.
- 본문에는 민감하지 않은 핵심 결과를 한 문장으로 요약한다.
- URL에는 결과를 복원하는 데 필요한 최소 입력값과 계산 정책 버전만 넣는다.
- 공유 URL로 진입하면 입력값을 검증한 후 자동 계산한다. 잘못된 값은 무시하고 기본 입력 화면을 보여준다.

## URL 규칙

- 결과 복원 상태는 버전을 포함한 JSON을 Base64URL로 인코딩하고 `?s={encodedState}` 단일
  파라미터에 담는다.
- Base64URL은 암호화나 위변조 방지 수단이 아니라, 입력값이 주소창에 직접 나열되지 않게 하고
  사용자가 개별 파라미터를 실수로 수정하는 일을 줄이기 위한 표현 형식이다.
- 상태 envelope는 `{ "v": 1, "d": { ...계산기 입력... } }` 형식을 사용한다. 포맷을 변경할
  때는 `v`를 올리고 이전 버전 처리 여부를 명시한다.
- 날짜·금액 등 원본 입력과 결과 재계산에 필요한 정책 버전만 넣고, 계산으로 다시 얻을 수 있는
  결과값은 중복 저장하지 않는다.
- 디코딩 실패, 알 수 없는 버전, 필드 검증 실패는 사용자에게 페이지 오류를 표시하지 않고 공유
  상태를 무시한 기본 계산 화면으로 처리한다.
- Base64URL 인코딩 후에도 URL이 과도하게 길어지는 반복 입력형 계산기는 압축 또는 서버 기반
  짧은 링크를 별도 검토한다.
- 브라우저 주소 제한보다 메신저 미리보기·가독성을 고려해 공유 URL은 가능하면 2,000자 미만으로 유지한다.
- canonical 메타데이터는 쿼리와 무관하게 `/calculators/{slug}`로 유지한다.

## 공통 컴포넌트

`components/calculator/ShareActions.tsx`를 사용한다.

```tsx
<ShareActions
  title="만 나이 계산기"
  text={result ? `계산 결과는 만 ${result.fullAge}세입니다.` : "생년월일로 만 나이를 계산해 보세요."}
  url={result ? resultShareUrl : undefined}
  mode={result ? "result" : "calculator"}
  onKakaoShare={kakaoShareAdapter}
/>
```

- `url`을 생략하면 현재 브라우저 주소를 사용한다.
- `onKakaoShare`가 없으면 카카오톡 버튼은 비활성화되고 설정 필요 tooltip을 표시한다.
- 계산기별 UI는 SDK를 직접 호출하지 않고 카카오 어댑터만 전달한다.
- 결과가 바뀌면 `text`, `url`, `mode`만 변경하며 공유 버튼을 중복 구현하지 않는다.

## 카카오 운영 설정

1. Kakao Developers 앱을 만들고 Web 플랫폼에 운영 도메인을 등록한다.
2. JavaScript SDK를 로드하고 공개 환경변수의 JavaScript 키로 초기화한다.
3. 공통 카카오 어댑터에서 기본 Feed 템플릿을 구성한다.
4. 미설정·SDK 오류 시 링크 복사를 사용할 수 있도록 유지한다.

실제 도메인이 확정되기 전에는 설정을 완료할 수 없으므로 컴포넌트는 어댑터 주입 방식으로
준비한다. 키는 저장소에 직접 작성하지 않는다.

**코드 쪽 구현은 완료됐다**(`src/lib/kakao-share.ts`, 2026-09-13) — SDK는 버튼을 실제로
누른 시점에만 지연 로드하고, `NEXT_PUBLIC_KAKAO_JS_KEY`가 없으면 어댑터 자체가
`undefined`라 `ShareActions`가 자동으로 "설정 필요" 비활성 상태를 보여준다(계산기 쪽
코드는 조건 분기 없이 `onKakaoShare={kakaoShareAdapter}`만 넘기면 된다, 17개 계산기 전체
연결 완료). **남은 것은 순수하게 운영 계정 설정뿐이다** — 아래 "카카오 실제 활성화 절차"
참고. 이 저장소 코드만으로는 활성화되지 않는다.

### 카카오 실제 활성화 절차 (사람이 직접 해야 하는 부분)

1. [Kakao Developers](https://developers.kakao.com)에 로그인해 새 앱을 만든다.
2. 앱 설정 > 플랫폼 > Web에 실제 운영 도메인(`https://calc.konly.co.kr` 등, 로컬에서도
   테스트하려면 `http://localhost:3000`도 함께)을 등록한다.
3. 앱 설정 > 앱 키 > **JavaScript 키**를 복사한다(REST API 키·Admin 키는 서버 전용 비밀값이라
   절대 안 됨 — JavaScript 키만 브라우저에 노출해도 되는 공개용 키다).
4. 배포 플랫폼(Vercel 등)의 환경변수에 `NEXT_PUBLIC_KAKAO_JS_KEY`로 이 값을 등록하고
   재배포한다. 로컬 확인용으로는 저장소 루트에 `.env.local`을 만들어 같은 키를 넣는다
   (`.env.example` 참고, `.env.local`은 `.gitignore`에 이미 포함되어 있어 커밋되지 않는다).
5. 재배포 후 아무 계산기 상세 페이지에서 "카카오톡" 버튼이 활성화되고, 눌렀을 때 실제
   카카오톡 공유 시트가 뜨는지 확인한다.

## 접근성·오류 처리

- 모든 버튼은 최소 44px 높이를 확보한다.
- 새 창을 여는 X 링크에는 `noopener noreferrer`를 지정한다.
- 복사·공유 성공, 취소, 실패 메시지는 `aria-live="polite"`로 알린다.
- Web Share API 미지원 시 버튼을 숨기되 링크 복사는 유지한다.
- 사용자가 공유창을 닫은 것은 오류가 아니라 취소로 처리한다.
